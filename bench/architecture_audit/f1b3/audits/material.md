# F1b3 material/resource semantics audit

Audit-only baseline: `ed2ac1537b2878a7b346652bedf134e9bd312007`, branch `feat/f1b3-mesh-semantics`, repository `/home/bend/.cache/rusty-tiles-f1b3-semantics`. No Cargo or producer invocation and no production edit was performed for this note. Observations below are static source findings; no new runtime conversion defect is claimed.

## Existing candidate foundations and limits

`source.rs::materials` admits only `pbrMetallicRoughness.baseColorTexture`, using UV set zero. Material scalar factors, alpha cutoff/mode and doubleSided are checked; labels are removed while other accepted presence/omission is retained. `primitives` accepts POSITION/NORMAL/TEXCOORD_0 and checks every declared primitive's required UV against only baseColorTexture. `Triangle` owns corner positions, normals, one UV set and material identity. Reflection corner swaps happen before each channel decode, a useful candidate foundation for companions.

`source/texture.rs` checks every declared image/texture/sampler, including unused entries. Image ownership and copying are bounded independently of publication; buffer-relative accessor overlap, MIME/signature and PNG/JPEG decoding are checked. It has no material-role assumptions and should remain a bounded image admission/forwarding module. Logical image identities remain separate even when physical resource capture aliases; selected closure is based on image index, not byte digest.

`encode.rs::material_texture` is one-slot logic used by global used-image closure, leaf texture closure and material remapping. The primitive grouping key is material plus normal/UV0 presence. Its missing-UV assertion also checks only baseColorTexture. Extending admission alone would leave incomplete publication and wrong local references; all three paths must change together. A single fixed enum of five core material texture roles or a small fixed path list is sufficient; no extension registry/framework is needed.

`source/json.rs` rejects duplicate keys and checks container-specific padding. No new JSON interpretation is needed for additional core material fields. Existing `uint` accepts integer JSON storage only, although glTF permits mathematically integral decimal/exponent notation; that is a static restrictive-profile observation, not a reproduced material loss defect or a requirement to add a general JSON rewrite here.

The F1b/F1b2 contract files and historical Python receipts are useful provenance, not independent proof of proposed new roles. The existing independent `tests/f1b_oracle.py::resources` and `used_resource_ids` similarly resolve only baseColorTexture; reusing them unchanged cannot establish additional-slot closure. Its current refusal corpus intentionally rejects the proposed new material/attribute semantics and therefore needs a precise contract revision.

## Proposed smallest useful extension

1. Admit exactly five standard core texture slots: baseColorTexture and metallicRoughnessTexture under pbrMetallicRoughness; normalTexture, occlusionTexture and emissiveTexture on material. Each binding has a checked texture index and optional texCoord selecting 0 or 1 (omission means zero). Preserve omission versus explicit zero and all accepted factor/scale/strength fields. Only dependency indices change in leaves.
2. Every declared primitive that uses a material must supply each UV set referenced by any of its five bindings. Apply this to unused meshes too, consistently with whole-document admission. UV1 requires UV0 because indexed semantic sets are consecutive. Sets >=2 are valid-but-excluded Unsupported; malformed/noninteger/negative selectors or out-of-range indices are InvalidInput. A primitive can retain unreferenced UV attributes.
3. Add TEXCOORD_1 in the same slice: mixed per-role UV selection is necessary useful material semantics and prevents index-only material support. Preserve independent corner association for each set through index expansion/reflection/partition/regrouping.
4. Add authored TANGENT companion with normalTexture, with an explicit baking policy below. Adding normalTexture while dropping authored tangents would silently alter tangent-frame meaning. COLOR_0 is independent of adding textures but is a small useful companion: linear RGB/RGBA multipliers, normalized u8/u16 or float, RGB implicit alpha one, preserve alpha association with MASK. Admit finite COLOR_0 values in [0,1]; finite out-of-range float colors are Unsupported by the bounded producer rather than presumed malformed, because the pinned specification requires clients to clamp and does not alone prove source invalidity. It must not be confused with sRGB texture bytes.
5. `normalTexture.scale` is any finite number (including zero/negative), with implicit default one; the pinned schema imposes no [0,1] or nonnegative range. `occlusionTexture.strength` must be finite in [0,1], default one. Preserve field presence. Other scalar restrictions retain existing profiles.
6. Global selected image closure and each leaf's local material->all-slots->texture->image/sampler closure must be exact and deterministic, deduplicating source image indices without conflating different textures/samplers. A shared image may be used by different color/data roles; its transfer function belongs to the material role, never image ownership. Forward original PNG/JPEG bytes once per selected image identity. No unpacking/repacking channels, atlas, image mutation, mip generation or implicit defaults.
7. Keep local dependency capture, snapshot and source/output alias policies bounded as F1b2 candidates. No automatic retention of legacy atlas, placement, LOD, extensions, material extras or implicit tiles. Keep BLEND excluded because partitioning cannot preserve draw order.

## Normal-map baking boundary

This is the substantive semantic decision before implementation. Existing geometry bakes accumulated world transforms into vertex data. For an arbitrary nonuniform world linear map A, source shading evaluates a tangent-space normal then transforms it with A^-T. An identity-node leaf with independently normalized transformed NORMAL/TANGENT and reconstructed orthonormal bitangent generally cannot represent that same anisotropic mapping for every texel using one scalar normal scale. Normalizing A*t and changing tangent handedness alone does not establish appearance preservation.

Recommendation: a normal-mapped or authored-tangent selected primitive is admitted only under a conformal **accumulated world** linear transform (uniform absolute scale times orthogonal matrix, reflections allowed), with a documented tolerance. Checking local node scales alone is insufficient because composition may introduce shear/anisotropy. Require authored NORMAL and TANGENT for normalTexture in this bounded slice; glTF-valid missing companions are Unsupported, rather than promising unevidenced generated-Mikk equivalence after baking and regrouping. Require tangent XYZ unit length and W +/-1. The pinned specification does not require authored normal/tangent orthogonality; conformal transforms preserve the given relation, so do not classify nonorthogonality as malformed. Mixed W across a normal-mapped triangle defines an undefined tangent space under the specification and is deliberately Unsupported for this profile, not InvalidInput. Malformed W/nonfinite values are InvalidInput; nonconformal transform/missing authored companion is Unsupported. Use an explicit accumulated Gram-matrix conformality check M^T M≈s²I (attribute audit suggests f64 relative threshold 1e-10). Under conformal mapping, transform tangent XYZ by A and normalize, transform normals by A^-T and normalize, multiply W by sign(det(A)), then apply the same reflection corner permutation to every channel. This is a proposed restrictive producer profile, not a claim these restrictions are required by glTF.

If a wider normalTexture profile is desired, retain/prove world/node representation or independently prove frame equivalence; do not silently invent new normal textures or accept nonuniform cases based on positive flat-normal tests. Parent/attribute audit must settle this policy jointly before production changes.

## Independent proof required

Author additional positive fixtures independently, with analytically different UV0/UV1 corner values, distinct slot images and distinguishable channels/factors, multiple samplers on one image, one image shared across data/sRGB roles, absent versus explicit default texCoord/scale/strength, zero/negative scale, strengths zero/one, selected/unselected meshes and image-only non-base-color closures. Test all slots individually and jointly, multiple leaves and reflections. Verify source-driven oriented corner associations and material role->UV set->texture->sampler->raw image/pixels paths, not archive hashes or self-generated expected output.

Sensitive controls must detect a role index changed to another valid texture; metallic/roughness or normal/occlusion binding exchange; UV selector changed without changing plausible geometry; remapped wrong local resource; deleted additional-only image; orphan image; changed scale/strength; invented default field; dropped UV1/color/tangent; tangent handedness corruption under reflection. Runtime/CLI/Python frontends and report/3TZ closure parity remain separate evidence.

For normal maps, independently compute source shading direction for a nonflat texel and analytic conformal reflection/rotation. Also explicitly refuse a nonuniform world transform and a nested composition whose locals look innocent but accumulated linear map is nonconformal. Viewer checks should use visibly nonflat normal/data maps and real consumer routing; a base-color screenshot is not additional PBR evidence.

Existing F1b/F1b2 independent geometry, image bytes/PNG/JPEG provenance, URI, lifecycle and finite-resource evidence must be replayed against the final binary; previous receipts are baseline historical evidence only. Broader legacy advertised-use removal/retention decisions remain separate roadmap obligations.
