## Decision

No new **F0 opaque-package acceptance blocker** found. F0 does not certify scenes or migrate converter jobs; accepting opaque malformed scene payloads is intentional. Its new stored archive serializer, file publisher, synchronized first-cause gate and adapter evidence earn **bounded retention candidates** for their stated file-pack contract, subject to supported-platform evidence. Broad legacy converter publication/observation is still outside that result.

**Do not use current built-in `validate` success as independent mesh/scene acceptance.** Current executable probes accept missing required GLB binary data and geometry outside declared bounds. Make the format/validator proof slice precede reliance on candidate validation in mesh migration. Existing independent coordinate and geometry oracles can be retained selectively; there is no evidence-based reason to rewrite every algorithm, nor to retain any whole subsystem unconditionally.

## Executed observations and their limits

1. **Validator accepts an invalid GLB binary range.** Independent byte fixture declares a 36-byte POSITION buffer/view and three vertices; actual BIN chunk has zero bytes. F0 `convert` succeeds, as its opaque contract permits. Native CLI `validate` also returns exit 0, `ok:true`, with checks including `structure`, `bounds`, and `geometricError`. Source `src/validate.rs:217` reads GLB JSON/header, and `:508` counts POSITION accessors without validating actual accessor/view/BIN ranges. This is concrete validator coverage failure, not a package failure. Rejection obligation should be explicit before calling this scene validation.
2. **Validator does not check decoded geometry against tile bounds.** A valid independently generated GLB triangle has every coordinate >=1000; manifest box spans x/y `[0,1]`, z `[-0.5,0.5]`. `validate` returns the same success. CLI docs accurately specify child-bound containment rather than decoded geometry containment; README's broad “bounds” wording and result check names must not become a stronger acceptance oracle. This is a concrete missing check if later acceptance requires content containment, rather than an established violation of the narrower CLI contract.
3. **Sampled mesh estimator is not an upper bound.** Direct call to current `hlod::two_sided_error`: parent is one flat triangle; children contain 3000 triangles, 2999 copies of that plane and triangle 1 with two vertices at z=100. Result is **0 m**, while each raised vertex is exactly **100 m** from the parent surface. `src/hlod.rs:443` builds vertices plus centroids and strides to cap 4096 samples; all spike samples are skipped. This proves the estimator's limitation for supplied meshes, **not** that a production simplification generates this parent or publishes underbounded geometricError. `docs/FORMATS.md:53` already disclaims a universal visual-error guarantee. Settle whether refinement uses a sampled estimate or a conservative bound; do not silently rename the estimate a guarantee.
4. **Legacy CLI geographic-offset rejection remains observable.** Current native CLI tiny geographic GLB + `--sourceOffset 1000 2000 300` returns data error / exit 3. Current Rust/Python ignored-offset, codec-default and callback-after-publication cases were **not rerun** here; baseline evidence and unchanged old paths support follow-up, not a fresh frontend matrix.

## Trackable pre-0.4 work packages and order

1. **Coordinate / geometry foundation proof, bounded domains.** Write a support matrix for local, geographic and declared horizontal coordinates: axis order, metre heights, finite/range/refusal rules, offset/placement and normal conventions. Retain analytic and frozen references; add independent oriented triangle/world-position/normal checks for transformed source and batch reorder/fallback. Add brute-force independent nearest-triangle and containment controls for grid/OBB across degenerate, large, thin and near-boundary inputs. Require known-corruption controls (wrong axis, scale, hemisphere, normal transform, bounds) to fail. Outcome: retain particular math/transform kernels or rework measured failures; no general CRS rewrite preauthorized.
2. **Format / validator proof, before mesh acceptance.** Give built-in validation an explicit structural versus decoded-semantic scope. Reject missing/overflowed accessor and buffer ranges, malformed GLB/B3DM framing and nonfinite data under that scope. Decide decoded content containment separately and test independently. Independently decode subtree address/rank/world transforms and compare reachable contents to a known model, not only expand_tileset. Carry the two new byte fixtures as negative controls. Keep official validator/browser checks complementary. Ensure geometricError monotonicity is not advertised as measured approximation accuracy. This can run alongside package1; only required subset blocks mesh.
3. **One real mesh vertical slice.** Rust/CLI/Python shared mesh request and defaults; source preparation before staging; job-local observer/first-fatal behavior and new completed-file publication. Initially static POSITION/NORMAL/TEXCOORD_0 + documented materials, explicit local/declared coordinates, one archive output. Preserve opaque wrap only where source semantics/resources are actually retained. Independently decode raw input and output, compare oriented triangle multiplicity, attributes, material/alpha/UV texture mapping and resource closure; use atlases with spatially unique texels, not solid colors. Exercise small-wrap and forced-pipeline paths. Add off-sample spike/reordered meshes, curved/thin/folded surfaces and measured parent-to-original errors; explicitly choose sampled-estimate versus bound policy. Extend memory/disk/FD measurements to geometry/image/member count and worker count. Retain algorithms only per accepted case; replace proven bad boundaries without a universal converter framework.
4. **Directory publication with one real directory consumer.** Choose a raster or terrain operation already producing directories. Pin supported create-new/replace semantics per platform, including reader visibility, cleanup, failed replacement/restoration and retained recovery paths. Test a competitor installed at permission, writer/finalizer/report/observer faults, and restore failure; do not infer directory guarantees from tempfile file persistence. Independent filesystem observer must check preserved competitor/previous content and reported terminal state. No universal directory atomicity or durability claim. This need not block archive-only vector transactions.
5. **Vector acceptance transaction slice.** Readers return domain rejection separately from fatal source/storage/observer errors. Commit rows/counters/success diagnostics together only after feature acceptance. Reproduce natural oversized polygon rollback and injected acceptance I/O before/after writes, asserting accepted counts/reports/content agree and fatal IO never becomes skipInvalid. One portable archive consumer first; native reader follows the same contract. Separately accept planar hole/fragment topology using independent union/symmetric-difference/overlap and boundary predicates; explicit repair/outline/3D policies have their own expected geometry. Do not approve all vector LOD/repair via the frozen encoder.
6. **Point and remaining vector semantic proof.** Track point and vector sub-results separately: required source field inventory, typed precision/nulls/identity, all full-detail source records/segments exactly once, decoded placement/bounds, parent approximation policy, chunk/worker/order invariance. For the large point audit add omitted-field and incorrect-POSITION controls. Require predetermined tolerances, not only tolerances copied from output report. Cover LAS/LAZ formats/EVLR/extra dimensions and supported source geometry classes; deferred/unsupported classes must remain explicit. Evaluate reuse fingerprints and cached contents against independently changed source fields/geometry/capabilities rather than only byte equality.
7. **Raster / terrain / native evidence.** After directory contract, prove one explicit image/mask/alpha or DEM/height recipe with analytical constant/ramp/impulse inputs and predetermined expected samples. Separate source-data retention, display resampling and terrain-added approximation error. Independently check seams, nodata/coverage, quantization + interpolation + simplification accounting and extreme geographic cases. Native preparation must resolve only required drivers/grids/encoder and expose truthful selected backend/refusals. Test actual supported installed platforms/wheels once implementation stabilizes; historical oracle parity and handle lifetime review remain supporting evidence only.

Suggested roadmap dependency: **1+2 -> 3**, with **4+5** as the next bounded consumers, then **6+7** and final supported-platform/install/browser/resource acceptance. Package2's minimal GLB/scene evidence must land before `validate` is treated as mesh's acceptance oracle; broader validator formats may continue later. No full async engine, registry, generic transactions or indiscriminate algorithm replacement is required by these observations. Before 0.4 every advertised operation must either earn scoped acceptance or be deliberately removed/deferred with its public contract updated; old suite success alone cannot exempt it.
