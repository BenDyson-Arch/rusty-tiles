# F1c1 spatial disposition

Audit baseline: `71cd11dcdb226ce7639912dba85adf0b2f35048b`, before production implementation. Current code and historical contracts were candidates. The accepted contract is [f1c1-contract.md](../../../docs/architecture/f1c1-contract.md). No broader CRS, picking or release claim follows from this slice.

| Component/use | Decision | Independently justified meaning and proof limit |
|---|---|---|
| F1b3 selected-node f64 bake and local f32 leaves | Retain within admitted profile | Rigid root placement adds no ECEF f32 bake or new companion rounding. Existing source-node/tangent/reflection/PBR admission remains required. Replay source and decoded fidelity. |
| Complete-triangle partition membership | Retain | Translation/rotation does not alter membership or triangle/companion multiplicity. Local/placed GLB byte equality is checked on bounded workloads. |
| Private outward local boxes | Retain with extended evidence | Stored local vertices are enclosed exactly; root affine transforms centers and half axes into world OBBs. Independent reader must prove full transformed enclosure, including zero extents and parent bounds. |
| Duplicate Y-up conversion in partition/placement | Replace with one private concrete helper | Two actual consumers require B(x,y,z)=(x,-z,y); root's quaternion axes are ENU. Runtime content applies B once. No generic matrix framework is justified. |
| Direct manifest/report construction | Rework | Prepared resolved placement supplies one exact column-major root transform and normalized report. Raw request choices never reach numerical encoding. Local uses explicit identity. |
| Legacy georef WGS84 forward and ENU formulas | Retain mathematical meaning; replace unchecked policy dependency | Independently derived Decimal/cardinal fixtures support forward formula. New placement owns finite/domain/quaternion/precision admission. Pole longitude and geodetic elevated up follow declared cartographic input. |
| Legacy public Cartographic/RotationDegrees/root_transform | Replace for bounded operation | Unchecked fields and Cesium HPR semantics do not define the new API. One ENU-active XYZW quaternion avoids a second Euler convention. |
| ECEF f32 placement bake or per-leaf rebase | Remove from proposed design | Earth-scale float32 spacing is0.5m; the independently sampled direct bake lost0.0878m. F64 rigid root preserves existing local storage precision without resource duplication. |
| Legacy bbox/mesh CRS resolver/Jacobian/guessing dependencies | Remove from new bounded dependency path; defer advertised legacy routes | Rigid placement needs neither source CRS projection nor ECEF inverse. General axes, projected offsets, datums/grids/epochs/geoid corrections require a separate admitted operation and references. |
| Local author metre offset | Support with explicit replacement contract | Post-node/pre-B Y-up translation; root translation C+FQB(offset) retains offset in f64. This is not SourceOffset or ECEF displacement. Sensitive nonzero rotated-offset controls catch order errors. |
| Source metre limits and placement numerical domain | Retain local limits; replace arbitrary altitude caps with one derived magnitude budget | Existing1e6m local component limit preserves declared f32 storage allowance. Additional placement target is1e-6m against independent arithmetic on stored coordinates; budget2^26m is an engineering decision requiring exact boundary comparison and platform probes. |
| Routing geometricError | Retain explicitly scoped metric | Local conservative diagonal with minimum1m; leaves0. 3D Tiles1.1 scales error by largest transform scale, which is1 for rigid placement. World AABB diagonal is rotation-dependent and must not replace local metric. No approximation/Hausdorff promise. |
| Source identity/picking | Defer encoding to F1c2 | Selected scene/node(instance)/mesh/primitive/triangle/corner association must originate before partition and survive reflection/grouping. Coordinates and names cannot establish unique identity. No unused speculative identity fields are needed here. |

Executed preimplementation design probes used independently authored65-digit Decimal forward arithmetic and quaternion vector rotation. Eleven anchors gave maximum ECEF component difference9.81e-9m; a proposed numerical-budget boundary with large offset/nontrivial quaternion gave8.68e-9m. These are design evidence, not candidate execution or browser acceptance. Cesium's elevated ENU convenience function uses an ellipsoid normal of the elevated Cartesian point: at100Mm height/45° latitude its basis differed by0.002236 from the declared cartographic frame. Freeze Cesium origins/surface cases separately; its convenience orientation is not the elevated-frame oracle.

[resource_probe.py](resource_probe.py) records pinned-binary100k triangle and4096 shared-primitive local/placed workload pairs, exact GLB/image identity, finite bounds, direct child wait4 RSS, sampled descriptors/threads/children/scratch and cap refusals before missing-source/output-parent access. These finite concrete measurements support the small placement representation; they do not prove asymptotic constant cost, hard universal resource bounds, complete world OBB/PBR truth or all viewer precision. Final source/artifact identities, sensitive independent spatial controls, actual viewer placement and a nonauthor review remain acceptance owners.

Primary meaning: [pinned Khronos glTF](https://github.com/KhronosGroup/glTF/blob/8e798b02d254cea97659a333cfcb20875b62bdd4/specification/2.0/Specification.adoc) for source metre/Y-up/node/attribute semantics; [3D Tiles1.1](https://docs.ogc.org/cs/22-025r4/22-025r4.html) for content/box transforms and error scaling; [ESA ENU/ECEF derivation](https://gssc.esa.int/navipedia/index.php/Transformations_between_ECEF_and_ENU_coordinates) for cartographic basis; [PROJ cartesian conversion](https://proj.org/en/stable/operations/conversions/cart.html) for ellipsoidal-height/ECEF meaning. The quaternion admission tolerance, source restrictions, numerical budget and routing metric are explicit profile choices.
