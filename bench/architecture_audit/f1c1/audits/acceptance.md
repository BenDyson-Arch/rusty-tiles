## Findings and recommended contract

**Use explicitly local metre/Y-up input, with either unplaced-local output or a rigid Earth placement. Retain local f32 geometry and express Earth placement by a serialized f64 root transform.** This follows a measured precision distinction, rather than the existing legacy representation: an independent audit point with 1–3 centimetre local coordinates at Brisbane loses 0.1128491163 m when its absolute ECEF coordinates are cast to f32, versus 8.36e-10 m when local coordinates are cast to f32. Rebase/bake alternatives are valid candidates only with a declared origin, inverse frame, separate rounding budget and actual consumer evidence. This slice gains no needed feature from those extra stages. Direct ECEF f32 baking should fail the precision control.

Admit WGS84 ellipsoid anchor longitude/latitude in degrees, height in ellipsoidal metres, without inferred datum, geoid, grid, epoch or source CRS conversion. Define the anchor frame analytically from supplied cartographic angles; do not infer it from ECEF inverse coordinates. The NGA defining constants are `a=6378137 m`, `1/f=298.257223563`, `e²=f(2−f)`. For longitude λ, geodetic latitude φ and ellipsoidal height h:

```
ν = a / sqrt(1 − e² sin²φ)
O = ((ν+h) cosφ cosλ, (ν+h) cosφ sinλ, (ν(1−e²)+h) sinφ)
E = (−sinλ, cosλ, 0)
N = (−sinφ cosλ, −sinφ sinλ, cosφ)
U = (cosφ cosλ, cosφ sinλ, sinφ)
B = [E N U]
C(x,y,z) = (x,−z,y)    # glTF Y-up to tile ENU/Z-up, determinant +1
```

Identity orientation consequently maps source +X to east, +Y to up, and source −Z to north. Source transforms are glTF column-major `parent*(T*R*S)`. The placement orientation must identify its frame: recommend an active proper quaternion XYZW acting in local ENU **after C**, with column-vector multiplication. The composed world point is `O + B Q C (N_source p + d)`, where optional d, if admitted, is in source metre/Y-up axes **after accumulated source node transforms and before C**. This offset is distinct from anchor height; translated source instances all receive the same post-node offset. If offset is deferred, authored node translation is the explicit replacement for local origin adjustment; do not pretend it supplies arbitrary projected-coordinate shifts.

For the root representation, bake `N_source` into the existing local content as before and emit root `R=[B Q, O; 0 0 0 1]`; applying d in local prepared geometry is simple but changes source storage error and must be bounded. An equivalent placement-only translation `O+B Q C d` can preserve baseline leaf bytes, but then report/contract/world oracle must state d contributes to root translation rather than ECEF axis addition. Pick one representation before authoring tests. Do not confuse the complete semantic expression above with a demand to rebake Earth coordinates.

**Quaternion versus Euler choice:** quaternion avoids an additional public Euler convention, gimbal presentation ambiguities and angle wrapping, at the price of requiring XYZW/unit/sign rules. Recommend XYZW, finite components, a unit norm tolerance explicitly bounded (existing source quaternion policy is 1e-6), normalization only within that tolerance, with q and −q representing identical rigid orientation. Optional identity orientation must be explicitly specified as the one API default if retained. Euler is acceptable if actual user use cases need it, but the contract must fix local ENU versus source Y-up, active/passive rotation, signs, intrinsic/extrinsic interpretation, multiplication order and degrees. Legacy Cesium HPR is heading around −Z, pitch around −Y, roll around +X; those names do not independently justify admitting that convention. A three-axis noncommuting example is mandatory whichever API wins. Do not admit quaternion and Euler simultaneously without a user need and conflict policy.

**Geographic domain:** recommend a bounded anchor profile such as longitude [−180,+180], latitude [−90,+90], finite ellipsoidal height |h|≤1,000,000 m, stated as producer policy. This keeps all anchors away from Earth centre without an inverse/conditioning fallback. Bounds are provisional until root consolidates the contract. Both antimeridian endpoints are physically equivalent; decide whether report preserves the request or canonicalizes it, and test that rule. Supplied longitude determines east/north at exact poles; cartographic position is the same for all pole longitudes but orientation is not. Test exact poles and nearby values separately. Do not silently use `atan2` or Cesium's Cartesian-pole fallback to discard the supplied meridian.

Cesium1.146 ordinary ENU construction uses `ellipsoid.geodeticSurfaceNormal(origin)` on its elevated Cartesian origin; this is not, in general, exactly U from the supplied cartographic φ. At (37°,48°,1,000,000m), the independent discrepancy is 0.00045326379 rad, or 0.453264m over a 1000m up vector. Its Cartesian-pole special branch also chooses a conventional meridian. Therefore Cesium helper agreement is supplementary evidence, not the accuracy oracle. The actual consumer must consume the serialized matrix unchanged.

## World reader and tolerance requirements

The reader must derive source truth from independent source bytes/request, never from `conversion.json` or production helpers. Decode candidate GLB and all glTF node transforms, apply C exactly once, then root/child transforms in column-major parent*child order. Current profile emits a rigid root and identity leaves, but the reader's chain implementation should self-test an independently authored nonidentity child and GLB node; candidate profile still rejects unexpected child transforms. Otherwise a reader that accidentally ignores a chain step can pass solely because producer omits it.

Existing `f1a_oracle.inspect` requires identity root/leaf transforms. `f1b_oracle.inspect`, called by F1b3, disallows root transforms and hardcodes local profile/report. Their world checks cannot be treated as placement proof. Prefer a small explicit keyword seam in F1b's inspector for independently supplied expected root/report profile fields, preserving its defaults. It still matches **local** corner/material truth and checks the original archive index/CRC/member closure. F1c1 owns new raw serialized-transform/request/report comparison and complete world chain. Do not add an unchecked callback that can suppress assertions or obtain expected values from output. Do not repurpose the old local comparator into a world comparator with its old tolerances.

Stripping root transform and rewriting report in a new synthetic archive can provide only a bounded local PBR/geometry regression proof. If chosen, original index/CRC/report/root checks must already pass independently, and transformed-archive receipt must clearly identify itself as a projection rather than evidence about original world geometry. The explicit seam avoids that repacking and keeps original byte provenance visible.

For rigid OBBs, transform centre by affine matrix and each half-axis by its linear matrix; enumerate all eight child-box corners for ancestor containment. Handle zero half extents by projection onto unit rigid basis (assert perpendicular component≈0) rather than inverting a singular half-axis matrix. Check candidate geometry in both local stored-coordinate bounds and world transformed bounds. A bounds control must mutate only bounds while preserving all geometry/root/report plausibly; a world-transform control must mutate only transform while bounds stay locally plausible.

Preserve the prior local storage tolerance `max(1e-6m, |computed local component|*2^-24)` for POSITION, companions and f32 channel tolerances. Never substitute |ECEF| in that expression: it would allow ~0.38m at Earth scale. Rotate the local three-component storage-error budget into the world frame, or use its Euclidean norm as the conservative world storage budget. Independently compare serialized f64 O to Decimal anchor (suggest 1e-8m); BQ components to independent rotation (suggest 2e-15); final stored-world reconstruction to the emitted-chain arithmetic (suggest 1e-7m over this bounded domain). These are proposed numerical budgets, not already agreed limits. At tiny local extent, world-box checks need f64 addition/ULP allowance; do not enlarge source-to-output material/world accuracy tolerances merely to make containment pass. Record storage-versus-analytic targets separately.

Routing GE retains its declared empty-root selection meaning, not a Hausdorff/source-quantization/LOD bound. Under rigid root placement it is unchanged in metres. Rotated world AABB diagonals inflate with orientation and are not an equivalent formula. If reporting world bounds, distinguish oriented transformed tile bounds from an enclosing ECEF AABB. Leaves still carry GE0 relative to stored full-detail geometry; that never asserts zero source-to-storage rounding error.

## Consolidated coordinator choices received after the initial audit

These agreed choices supersede the provisional domain/API recommendations above. `MeshPlacement` is Local or Wgs84. Wgs84 carries raw anchor `[lon_degrees,lat_degrees,ellipsoidal_height_metres]`, XYZW orientation with unit-norm tolerance1e-12 and exactly one normalization, and `scene_offset_metres` in post-node source Y-up axes. Local carries no offset or orientation. Orientation acts actively on ENU after Y-up conversion. In the notation used in this report, root linear map is `B Q`, root translation is `O+B Q C d`; all content remains baseline local f32. The root matrix is emitted even for Local identity. Report schema4/profile `f1c1-placed-gltf-v1` replaces the prior report, with `source_coordinates=local-gltf`, typed normalized placement parameters and root transform. Old local oracles may update expected report facts and accept explicit identity root via strict expectation seams; their geometry/material truth remains local and separate from F1c1 world proof. F1c2 is design-only in this slice.

The finite spatial budget is `a + abs(h) + offset_L1 + sqrt(3)*1e6 <= 2^26 metres`. Finite excluded budget returns Unsupported; malformed ranges, nonfinite request values and nonunit quaternion return InvalidRequest. This replaces the suggested |h|≤1e6 limit. A formula-defined cartographic frame remains defined even when negative forward height puts O at Earth centre; there is no reason to invent an inverse-frame singularity refusal. Add that acceptance case and negative heights below the ellipsoid's radial length.

The audit prototype was extended and executed with **21** anchors: the original16 plus oblique ±50,000,000m heights, equatorial h=−a, near-centre equatorial height, and near-centre polar height. Final receipts/fixture hashes record21; maximum f64-versus-Decimal coordinate difference is now7.45058e-9m. This larger observed error follows the declared larger magnitude domain; original16-anchor observation remains historical above. The code checks a strict magnitude-derived two-ULP f64 reference allowance (with3e-9m minimum) in its own float prototype, and it still does not execute production code.

Additional consolidated-contract acceptance requirements:

- State whether quaternion admission compares `abs(sqrt(sum(q_i²))−1)` to1e-12; squared-norm tolerance has a different boundary. Independently test immediately inside/on/outside that rule, zero, finite enormous components, nonfinite components and q/−q. Norm evaluation must not overflow into an accidental acceptance/normalization fallback.
- Exercise budget exactly at, immediately below and immediately above2^26, with height-only, offset-only and combined terms. Include equal-magnitude offsets with different sign/cancellation patterns and noncommuting q; do not replace the L1 bound with |sum(offset)|.
- Use the largest supported offset under mixed orientation when deriving the f64 root/world rounding allowance. An absolute1e-7m proposal may be too tight once several offset-rotation additions reach2^26 scale. Prefer a documented conservative e.g.32-ULP envelope at the declared world budget, plus independent small-scale anchor accuracy assertions. This is distinct from POSITION f32 storage error and must not let metre-size corruption pass.
- Compare raw original report/root with independently normalized request values and freeze full normalized parity across Rust/CLI/installed Python. Do not source expected placement from the report itself. Earth/Local identity equivalence may share content bytes while their typed report interpretation remains distinct.
