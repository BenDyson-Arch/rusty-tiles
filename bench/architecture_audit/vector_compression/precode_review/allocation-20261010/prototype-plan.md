# Bounded actual representation prototype decision

**An isolated representation prototype may now be authored.** Its source stays outside the repository and frozen prior packages. Before root compiles/runs it, freeze the concrete types, allocation order, checked capacity formulas, fixture identities, expected facts and sensitive controls for independent source review. This is preparation to resolve an unknown representation, not foundation implementation or a whole-P2 approval. The author owns source preparation; root owns serial two-core/nice10 compilation/execution and new source/artifact/output receipts. No user approval pause is required within the authorized audit.

## Smallest concrete candidate

Use the agreed flat arena, not a new per-object map framework:

- Immutable captured input bytes have one owner. The accepted C1 `CheckedDocument` and all RawValue values borrow those bytes. No Value roundtrip, additional JSON snapshot or decoded virtual buffer enters this prototype.
- `RawField<'a> = (Cow<'a,str>, &'a RawValue)` has one flat `Vec` backing. On the measured compiler target its element is40bytes. Allocate once with checked `size_of::<RawField>() * K`, from actual admitted K, using fallible exact reservation. Do not reserve configured max_nodes for a small document. Verify/report actual requested capacity. Every consumed property corresponds to a distinct admitted child node, so distinct root/buffer/view property occurrences together fit K. Retaining all K slots is a deliberately conservative concrete allocation; do not pretend only arena.len() bytes are owned.
- `FieldSpan {start,len}` uses stable arena indexes. The root and single real buffer use stack spans. Each physical view gets one descriptor and one finite action/edit record in an exact/fallibly reserved vector. Concrete Raw/Encode/ValidateIdentity alternatives must contain their actual range/count/stride/bound/edit fields; measure enum padding and descriptor size rather than reserving a dummy256bytes to validate the old coefficient. A shared reference reuses its physical descriptor. Distinct overlapping physical views remain distinct. No pointers into a vector that can grow, cloned per-reference plan, or retained graph framework.
- Count raw arrays through streaming `next_element::<&RawValue>` and drop each returned reference; do not collect a supposedly unowned reference vector. The iterator/parser is still a live scratch owner. Once actual V/A/declaration counts are known, allocate any needed descriptor/raw-reference arrays exactly once. An accessor array is not mandatory merely because A occurs in an old formula: use streamed temporary finite facts if the representation needs no retained accessor owners. Conversely, every genuinely retained accessor/association array must be a concrete charged owner. Name the prototype's fixture-supplied action selection explicitly if classification is supplied by independent fixture facts; it does not prove a source classifier.
- A custom Cow key visitor must implement `visit_borrowed_str` and fallible exact allocation in `visit_str`; do not assume `Deserialize<Cow<str>>` borrows unescaped keys. Own only escaped decoded keys. One source object contributes its fields once. Consume one decoder at a time and drop it before opening the next object, including count/classification passes. `String::push_str` must stay inside its secured capacity. Arena pushes cannot exceed the secured K capacity. The long escaped-key witness remains necessary: Cow alone does not remove its scratch plus owned-copy peak.
- Decode/classify actual extension declaration names during prepare into finite known facts, retaining raw declaration refs as needed. A string visitor can match decoded text without creating a String. Unknown/long names must take the bounded prepare/refusal path. Count/emission consumes those facts/raw refs and does not decode arbitrary declaration strings again. Opaque application schema/extras keys retain RawValue preservation. This is not a new policy bag.
- Use the actual finite edit fields and receipt facts as plain values. Report their `size_of` and any real heap owners. Stack headers are not separate heap allocations. Do not add artificial1024byte receipt storage. Paths, Job/runtime, source capture/recheck, publication, native decoding/encoding, producer bridge, installed adapters and full graph classification are outside this capacity prototype; the eventual integration must account for those owners separately.

## Source-derived ledger to freeze before execution

Separately account for (1) admitted-JSON work, (2) count/classify construction with already retained owners, (3) arena/descriptor/key construction, (4) decoder-dropped retained plan, (5) CountWriter, (6) final fixed-capacity GLB if retained as an existing mechanic, (7) dropping the plan before independent identity copying. A decoder/count pass and a second parser must not survive together accidentally.

For the flat candidate use explicit terms such as `K * size_of::<RawField>()`, `V * size_of::<PreparedView>()`, and exact retained declaration/ref capacities, instead of inheriting128K/256(V+A). Construction payload may provisionally use3J only under the disjoint-source/single-decoder/exact-key-copy schedule. Include the pinned u8 scratch initial minimum separately: the source's first nonempty scratch reservation may choose8bytes even for a one-byte required payload. Subsequent old+new growth is at most3times the new required source-backed scratch size. A conservative explicit small scratch allowance is needed; it cannot be hidden in a universal exact3J payload statement. After all contributing decoders drop, escaped owned-key payload is at most J. Ancestor keys and current-source key/nesting bytes must be accounted as distinct occurrences; duplicate parsing/copying invalidates that reasoning.

Any estimate/refusal check performed after JSON admission is precisely a **Plan preparation** boundary. Exact/one-below work refusal must precede Plan arena/descriptor/key allocations and callbacks/native work; it cannot retrospectively imply zero parser allocations or prove a pre-JSON whole-operation bound. The JSON/helper and source-read phases keep their existing held coefficient obligations. Typed prototype ResourceLimit should not require error formatting allocations inside the measured gate. It is a concrete pure prepare error, not proof of the later Job/CLI/Python causal route.

The meter precharges requested old+new and captures phase maxima/live/capacities before reporting. Record baseline source/oracle/fixture owners explicitly; measurement/oracle buffers are not production policy terms. Any detailed allocation-event trace must itself use separately excluded bounded nonallocating storage or disclose its allocation. Run no allocator-abort injection into serde's infallible internal growth and call it graceful refusal.

## Minimum meaningful probe matrix

Reuse the frozen10 admission/78 serializer inputs and immutable long-root-key case where relevant. Add only representation-specific witnesses:

1. Empty/one-field and many tiny physical objects, exact K/V/A, highK-smallJ, highJ-smallK, deeply nested raw values, long escaped root/buffer/view keys with late escapes, UTF8/escaped decoded-key equality, and varying escaped-key orders. Exact arena/descriptor capacities must hold and never grow; unescaped keys must borrow inside source, escaped copies must be separate. Once a contributing decoder drops, retained live bytes must match arena+descriptor+escaped-key+any real reference owners.
2. Shared references reuse the same span/action; distinct overlapping physical views allocate distinct descriptors. Unknown extension at each actually consumed profile position and a very long unknown declaration must stop in prepare without count/emission. A valid-ineligible natural stride remains Raw under fixture role expectations, not falsely classified malformed. These checks can be representation/domain seams; full semantic graph validity stays held.
3. Independent expected JSON/GLB bytes and count limits where the fixed serializer is reused; opaque numeric lexemes remain RawValue. Count/emission should allocate no arbitrary declaration-name copies. Copy identity only after plan/scratch drops; count source and new candidate separately.
4. Source-derived estimate exact admission and one-byte-below typed refusal before Plan allocation. Read an independent allocation trace/record, not the candidate's returned estimate, to reject controls that omit escaped keys, scratch, arena capacity, descriptors or reference vectors; miss old realloc storage; duplicate/retain a transferred owner; reserve the configured maximum; or reparse/clone a shared physical object. The old2J escaped-key underestimate must still be caught. A deliberately small wrong estimate must fail the observed requested-allocation comparison even when the budget boundary arithmetic itself passes.
5. Checked overflow/host-isize/u32 conversion and forced failure of the actual fallible arena/key/descriptor reservation seams, where practical, returning typed ResourceLimit. Keep those outcomes separate from infallible serde allocation failure and complete operation causality. Do not add a general allocator/runtime harness merely to cover a seam.

Before the root run, the independent reviewer can approve that **specific source/probe execution scope**. After the run, reconcile measured capacities/lifetimes with the source-derived algebra. If the candidate settles a faithful Plan mechanism, retain those exact types/algorithm/capacity decisions for future implementation or repin/review changes. This progression resolves the capacity unknown without requiring an unimplemented future production Plan as the prerequisite for writing an isolated prototype.
