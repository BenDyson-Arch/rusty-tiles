## Required standalone supported domain

The initial operation is one self-contained generated-family GLB v2 compressed by a lossless buffer-view transform, installed at its selected source pathname. File admission and format admission are separate. Regular local source files are supported; missing, directory, socket/FIFO/device and final symlink entries are refused before candidate creation. No external buffer/texture/resource discovery is performed by this operation. The precise generated-family JSON/extension domain belongs to the codec lane and must be explicit, rather than guessed from all glTF files.

Do not silently drop currently generated content: f32 POSITION VEC3 stride 12; normalized U16 quantized POSITION VEC3 stride 8 including padding; feature scalar U16 padded stride 4, f32 stride 4 and U32 stride 4; point/line/triangle/polygon offsets and loop/restart words including `u32::MAX`; raw BOOLEAN/INT64/FLOAT64/UTF-8 metadata and U32 string offsets. `list_fields=json` currently stores source arrays as JSON text strings. Preserve raw structural-array metadata views if the declared imported profile admits them, without claiming that the producer authors all structural-array forms. Fill content uses triangle primitives but its existing compression remains ATTRIBUTES; do not substitute triangle index encoding without independent equivalence proof. The codec lane supplies final admission decisions, not the lifecycle owner.

Unknown data retained by the chosen JSON contract must remain semantically exact, especially opaque number lexemes and metadata. Compression cannot introduce quantization, feature reordering, topology changes, metadata numeric rounding, lost unknown fields or extension/resource edits beyond the planned buffer/view compression fields. Already compressed inputs are recommended Unsupported in this first generated-uncompressed operation unless a separately proved idempotent plan is chosen; never infer that virtual fallback views point to embedded BIN. This deliberate refusal must be documented. Whole physical views, rather than individual accessor counts, own compression streams. Separately validate accessor windows and roles. Shared/interleaved valid glTF forms not emitted by the reviewed builders require explicit admission or Unsupported; accessor.count*stride=view.length is not a universal format validity rule.

## Source/path and in-place identity contract

1. Pure request validation checks a nonempty file path and limit algebra without filesystem mutation. Begin one Attempt, resolve publication support, and choose the source/replacement pathname before any callback or candidate creation.
2. Capture the requested spelling as an absolute path, reject final symlinks/nonregular entries, resolve the canonical selected entry and parent, then open read-only and compare admitted metadata with the opened regular file and held identity. Read in bounded chunks with cancellation checks, detecting excess/short reads. Retain immutable source bytes and one expected-source identity/metadata record. Preparation requires a stable source; metadata checks are detection, not an atomic snapshot against hostile concurrent mutation.
3. The replacement output is exactly the captured canonical source pathname. There is no second destination argument, create-new choice, overwrite flag, or same-file rejection branch for this first real operation. Intentional source/output equality is intrinsic. A separate destination operation would be a separately justified contract.
4. Fix absolute source, destination and parent choices once. A callback changing CWD cannot redirect reads, staging, publication or result identity. Canonicalized ancestor symlinks can be admitted at capture; later ancestor/namespace mutation is outside this bounded ordinary-filesystem profile. Final source symlinks are not followed. No openat sandbox is promised.
5. Hard-linked source names are permitted with named-entry replacement semantics: only the selected pathname receives a new inode; other hard-link aliases keep captured original bytes. Existing open readers may likewise retain the original object. This deliberately differs from direct fs::write modifying every alias. No claim that all aliases are compressed is made. Test alias bytes and both inode identities independently where available.
6. Before closing events/sealing, and after the final ready event has returned, recheck the original spelling and selected canonical entry against the held identity, regular type and captured metadata. A bounded exact-byte comparison against captured bytes should detect same-length callback writes that restore mtime; do not allocate another entire source Vec. Changed/deleted/replaced source or symlink substitution is a typed conflict and prevents installation. Rechecks themselves must be cancellable.
7. Close all source/recheck handles before publication as required by the supported platforms. The last source check and `Replace` are separate operations. There is a race afterward: another writer can replace/change the entry and `persist` can overwrite that writer. The supported domain requires exclusive stability of the selected source/parent from admission through installation; this operation is not an atomic conditional update. A fresh preflight or repeated metadata comparison cannot remove this proof limit. A true competing-writer no-loss guarantee requires a different platform primitive/locking contract, which is not justified by existing F0 evidence.

Point 6 is a proposed stronger callback-interference check, not an established existing capture behavior. Root must settle it with bounded probes before implementation. Its cost is a second streaming read with a fixed-size buffer. It does not justify removing the stable-source precondition in point 7.

Recommended filesystem-metadata choice: preserve captured portable `fs::Permissions` on the private completed candidate before sealing, so normal in-place use does not unexpectedly change access mode to F0's 0600. A permission-application failure is precommit I/O and preserves source. Inode, timestamps, ownership, extended ACLs, xattrs and all alias identities are not promised preserved by named-entry replacement. If root instead chooses private-candidate permissions, that must be documented as a deliberate behavior change and independently tested. Do not hide this choice under generic OutputPolicy.

## Smallest justified ownership/interface

Proposed deliberate API, naming still subject to final combined audit:

```rust,ignore
struct VectorCompressionRequest { path: PathBuf, limits: CompressionLimits }
struct VectorCompressionReceipt {
    before_bytes: u64,
    after_bytes: u64,
    compressed_views: u64,
    raw_views: u64,
    estimated_working_bytes: u64,
}
struct VectorCompressionResult {
    output: PathBuf,
    receipt: VectorCompressionReceipt,
    cleanup_diagnostics: Vec<CleanupDiagnostic>,
}
fn compress_file(request: VectorCompressionRequest, run: &RunControl)
    -> Result<VectorCompressionResult, JobFailure>;
```

One private resolved in-place source value owns fixed path, immutable source bytes, expected identity/metadata and validated limits. No public generic Validated<T>, filesystem/plugin registry, converter trait, universal context or publisher codec dispatch is needed. No output-policy field is needed when the operation intrinsically replaces its selected entry.

Shared format admission/planning supplies a validated view plan and checked accounting, and encoding consumes that plan. These functions receive byte slices or an admitted document representation, not source paths, RunControl, reporters or producer options. Codec errors remain ordinary typed format errors; orchestration maps them once. The producer's existing Value-to-raw serialization, if selected for one shared planner, is deliberate work with its own counted allocation, not a free bridge. The standalone result does not need an embedded report document or sidecar; receipt values freeze before seal. Legacy beforeBytes/afterBytes JSON is an adapter serialization choice only.

Default limits belong to one CompressionLimits::default owner. Core request validation lowers raw requests to validated values once; CLI/Python delegate to it, and producer obtains the same explicitly resolved codec policy at its own orchestration boundary. Final vector tile output `max_bytes` is a separate final-content limit, not codec RSS or source memory. Low stages never inspect options.meshopt, force, adapter defaults or operation identity again. Existing feature-fitting and final candidate encoding must use the same transform/admission rules to avoid admitting a feature with a different cheaper representation.

## Complete candidate and one Attempt

The standalone sequence is: begin -> pure validation -> read-only path/source capture -> bounded format admission/plan -> optional start event -> compression/serialization -> stage/write complete candidate -> freeze typed receipt -> final ready event -> source identity/content recheck -> close events -> seal/sync -> F0 Replace -> typed published result. Implementation may stage earlier once admission is complete, but every fallible producer step still occurs before seal/permission. Close admission only after every synchronous observer returns; no completion callback runs after installation. A single native encoder call can be noninterruptible; cancellation is checked before/after it and between view/chunk operations, with this latency stated honestly.

All precommit fatal causes enter the same Attempt first-cause arbitration: invalid input, unsupported source form, resource refusal, source I/O, allocation refusal, encoder/serialization/write/finalization/permissions failure, observer failure and cancellation. Every failure with a staging owner calls explicit staging.fail, preserving secondary cleanup errors/retained paths. No stderr defaults, message substring classification or exception-priority ladder belongs to core. A publisher failure after permission owns the primary outcome. A successful install remains successful when adapter printing or later cleanup diagnostics fail.

Producer compression remains a pure stage inside vector_to_archive's existing Attempt and accepted-member transaction. A typed codec failure propagates to that owner without a second control or standalone report. No in-place file publication occurs on producer workspace content. Archive candidate/readiness/report work remains before its outer publication gate.

The current runtime JobErrorKind has no ResourceLimit kind. If a requested storage limit is exposed, a minimal ResourceLimit variant plus exhaustive CLI/Python transport mappings is justified; calling it malformed data, I/O or an undifferentiated Unsupported loses useful cause. Codec FormatError already has a distinct ResourceLimit. Source conflict remains Conflict, request limit algebra InvalidRequest, malformed source InvalidInput and out-of-profile source Unsupported. Add no separate broad error hierarchy.

## Resource accounting and outstanding precode choices

No numeric source/JSON/view/accessor/default ceiling is accepted by this audit. Do not accidentally inherit C1 or mesh maxima: choose a finite profile against real generated cases, validate maximum/max+1 controls and account all simultaneous data before coding. Custom larger vector producer max_bytes settings must have an explicit supported/refused profile; narrowing ordinary generated quantized/polygon/metadata content is not an acceptable implicit fallback.

Codec-lane static formula for meshopt 0.6.2 vertexcodec.cpp bound at strides S=4/8/12:

`B(N,S) = 1 + ceil(N/256) * S * (S/4 + 260) + 32`.

Compute ceil without `N+255` overflow. Every host conversion, sum, product, alignment and start+bound operation is checked. A worst BIN bound is sum(raw view lengths) + sum(B for encoded views) + 7*view_count, with virtual fallback size separately summing aligned decoded compressed view lengths. Actual GLB total is 28 + align4(output JSON bytes) + align4(output BIN bytes); preserve the eight-byte view alignment and applicable absolute payload alignment contract. Output JSON grows from added view extensions and buffer records; source JSON size alone is not its bound. Count serialization or prove an explicit retained-source-plus-generated-field bound before allocating output storage. glTF count/stride, GLB u32 framing and host usize limits are separate checks.

Current `glb.rs` uses unchecked next_multiple_of, capacity arithmetic, packed_size increments and start+encoder bound resizing in this path; these require rework, not broad acceptance from count*stride alone. Avoid accidentally changing mesh's other codec consumer without its declared migration evidence.

At least these operation-owned simultaneous resources must be counted by phase: immutable full source; root JSON grammar scratch; decoded-key/scalar scratch and JSON pending slots/duplicate key sets; format plan records, retained number/key/text representation; rewritten-document/output JSON; compressed BIN capacity including encoder-bound temporary tail; GLB container capacity that currently copies BIN; fixed input/recheck buffers; receipt and retained raw-view descriptors. If any full document/bytes clone occurs, include it. Producer owns existing uncompressed geometry/BIN/Value and must count its overlap with codec work separately. Source bytes are not freed while a borrowed plan or final source comparison still uses them.

Prefer a precisely named `max_estimated_working_bytes` if limiting summed audited requested capacities. It is neither a process RSS limit nor a universal allocator budget. Record formula/version and actual requested high-water storage, distinguish estimates from measured RSS/allocator fragmentation/native stacks, and explicitly account parser scratch that can precede depth checks. An estimate that simply sums source+final output while omitting Value/JSON/encoder capacities is unfaithful. Do not advertise total resident-memory guarantees without their own executed evidence.

The minimal standalone descriptor/scratch profile can be one source handle and one identity clone during capture/recheck, one private candidate handle during writing, fixed chunk buffers and one candidate file on the same filesystem. Actual count and overlap must be measured; canonicalization/platform libraries may use transient descriptors. Successful operation holds old source storage plus candidate until installation; failed cleanup can retain the full candidate. Avoid adding a worker pool: view compression can remain serial, producer owns existing workers. Thread controls are operation-owned, not assumed overridden by RAYON_NUM_THREADS.

## Sensitive independent acceptance plan

Bind every execution and negative control to exact final source, executable, wheel, fixture and oracle hashes. Coordinator alone owns heavy builds/resource work under nice 10, two-worker and two-CPU limits; this lane performs no such runs. Fresh nonauthor review must inspect final source/evidence and judge declared proof limits. Applicable main CI, installed-wheel platforms and official Blender checks remain final-source gates, not inferred from current C1 acceptance.

1. Independently authored source matrix includes f32 and normalized U16 positions, every generated scalar feature type, point/line/triangle and polygon/restart words, raw numeric/string/boolean metadata, exact large integer and opaque numeric JSON, arrays admitted by the final profile, and distinct scenes/bounds/transforms. Independent meshoptimizer decoder compares every full stream byte including padding/restarts and every raw metadata view byte/decoded value, document reference/extension meaning and feature association. Existing writer or C1 reader is not sole oracle.
2. Admission controls include missing/truncated file, regular-type failures, symlink leaf, invalid/duplicate/deep JSON, bad buffer/accessor/view references, already compressed input policy, malformed/out-of-profile numeric layout, overlapping/truncated ranges, host-width and alignment overflow, encoder zero/failure and max/max+1 for each accepted ceiling. Every detected control must identify its intended boundary; malformed labels do not stand in for typed resource refusals.
3. In isolated subprocesses, change CWD in first/final callbacks and prove intended canonical output, source capture and untouched alternate directory. Test requested spelling with dot components and ancestor symlink admitted at capture. Disable path capture in a negative control; it must redirect or otherwise fail the independent identity assertion.
4. Verify equality is intentional, successful hardlink alias retains original bytes, named source inode changes, exact-byte source recheck detects callback overwrite with restored mtime, callbacks deleting/replacing/renaming/symlinking target abort before permission, and result identifies the installed selected entry. Use independent file IDs/byte hashes. Skip unsupported hardlink cases with explicit platform reasons, never count them passing.
5. Inject capture/read, format-plan, allocation, encoder, serialization, write/flush, permissions, candidate sync and install failure separately; each reached fault preserves original selected bytes and known aliases under supported stability preconditions. Inject temporary cleanup failure and inspect retained work plus secondary diagnostics. Inject postcommit temporary-name reoccupation and prove no unlink of competitor. Negative controls omit explicit cleanup, seal too early or write source directly and must be caught.
6. Observer failures at first/final event, cancellation during chunk/view work and immediately before permission, control reuse/reentry, repeated/concurrent independent paths, first-cause races and postpermission cancellation. Use a bounded one-attempt trace monitor. Negative controls nest controls, split cancel-check/install, emit after seal or rewrite committed success and must be rejected. No claim that same-target concurrent compressions are supported.
7. Reproduce the final-check/install window using a test seam and competitor mutation. Required finding is honest declared non-CAS behavior, not a false no-loss result. This control prevents overstating Replace. If product requirements demand unconditional competing-writer preservation, stop and replace the publication primitive/contract before coding rather than repeatedly preflighting.
8. Verify source permission policy on Unix and relevant Windows readonly behavior, destination-reader complete visibility, stale original handles/aliases, supported installation failure against directory/symlink interference, and explicit no durability claim. Cross-platform evidence cannot be transferred from Linux.
9. Measure fixed-worker source/JSON/view/accessor/codec cardinality scaling, requested-capacity high water, peak RSS, scratch bytes and descriptors on actual admitted boundary fixtures. Include maximum metadata/key/numeric lexeme growth, small-many-views worst padding, incompressible streams, larger compressed output, and producer raw-serialization bridge if used. Sensitive accounting controls omit source/BIN/JSON/encoder/parser scratch copies and must exceed or fail the independent estimator assertion. Record sample/platform limits; estimates and observed RSS remain distinct.
10. Rust/CLI/Python request/default/refusal/output-identity/typed-error parity and installed-wheel callback exception preservation. Producer max_bytes reflects final compressed content bytes; feature-fitting/final encoding share admission and resource profile. Archive independent inventory/decoder and actual pinned browser vector picking/metadata prove generated compressed candidates remain usable. Official Blender remains applicable regression acceptance, not a vector-draft consumer oracle.
