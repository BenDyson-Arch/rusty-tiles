# Minimal ResourceLimit ownership proposal — no production code

The new codec's finite requested-work refusal is operational `JobErrorKind::ResourceLimit`, distinct from malformed input, invalid option syntax, unsupported representation, native encoder failure and I/O. Add this one kind to the existing runtime enum when the representation/source slice is ready. Do not introduce a scheduler/error framework, dispatch flag or display-string classifier.

`ErrorDetail` already stores `Option<Arc<dyn StdError + Send + Sync>>`; `JobError::source()` exposes it, and cloning JobError preserves Arc causal identity. Add one internal constructor, e.g. `pub(crate) fn with_cause(kind, message, error: impl StdError + Send + Sync + 'static)`, that initializes the existing source slot. It needs no new path/stage fields or codec imports into runtime: the actual codec error owns its stage and typed failure details. Non-I/O ResourceLimit/native/format causes must not be wrapped in io::Error merely to reach the existing `io` constructor. Preserve an already-tagged checkpoint JobError unchanged so `same_cause` still identifies the original control abort.

The private consumer adapter chooses the kind once: actual ResourceLimit ->ResourceLimit; actual native EncodingFailure ->InvalidState; malformed/Unsupported internally authored producer bytes ->InvalidState; standalone external malformed/valid-excluded source retains its InvalidInput/Unsupported distinction. Pure codec code has no Job/runtime/publication imports. Its ordinary generic checkpoint failure is returned with exact identity to its owning caller, not rewritten into a format or resource error.

Producer transport uses existing `Error::Job(JobFailure)` and `From<Error> for FeatureFailure ->Fatal`. If the encoding owner only needs to transport a new cause before the outer attempt aborts, construct that existing JobFailure with empty secondary/retained paths/recovery; do not create another Attempt. The actual consumer/operation decides where the one existing Attempt records failure and cleans its owned candidates. This avoids calling a fictitious inner producer Job or a new publisher.

Static source confirms `fits_feature` propagates `emit(...)?`; Spool::insert propagates `fits_feature(...)?` rather than turning its error into false; final emit/encode also propagates Error. `FeatureFailure::Fatal` remains primary over rollback cleanup in `cleanup_failure`; vector `job_error(Error::Job(failure))` returns the original JobError. The new adapter must enter this typed path. Neither skip_invalid, split/simplify fitting trials, uncompressed fallback nor a rejected-feature warning may consume resource/native/checkpoint infrastructure failures. Fitting and final encode share the same validated limits/prepare/bridge/checkpoint policy. Existing source observations do not prove the new error route until the actual consumer has been implemented and exercised.

CLI owner: add `ResourceLimit -> ("resource_limit",1)` in the existing JobError CLI category mapping. Exit1 is an operational refusal, not exit2 request syntax or exit3 malformed-data classification. Audit each actual CLI route for `Error::Job`: an existing legacy generic `Error::category()` fallback must not accidentally replace the explicit Job outcome/category. Do not put CLI exit policy in the codec or runtime enum.

Python owner: `ResourceLimitError` already exists and is exported. `error_to_python(ValidationFailure::ResourceLimit)` already uses it; the missing route is JobFailure adaptation. Add the Job kind mapping `resource_limit` and `JobErrorKind::ResourceLimit ->ResourceLimitError` to `job_failure_to_python`. Preserve existing `.kind`, secondary diagnostics, retained paths and recovery metadata and original callback/signal exception behavior. No new standalone compression Python surface is implied. Required later installed-producer tests exercise both fitting and final new codec refusal through the existing public conversion route, rather than merely constructing an exception in-process.

Decisions settled precode: typed ResourceLimit, existing causal slot/internal constructor, Error::Job/Fatal transport, CLI category/exit1, existing Python exception/kind owner, original checkpoint identity and one Attempt. Actual P4 tests are logically after the concrete codec/producer source exists: inject ResourceLimit/EncodingFailure/authored InvalidInput/Unsupported/checkpoint separately at fitting and final; alter display strings without changing outcome kind; prove no skip/fallback/split continuation, one terminal cause and correct secondary cleanup; exercise reuse fingerprint/inventory/max_bytes and installed CLI/Python parity. They are required implementation acceptance obligations, not impossible prerequisites for authoring their implementation.

No changes in this package implement the constructor, JobErrorKind, producer adapter or frontend mappings. ResourceLimit remains absent from copied accepted runtime; these F0 probes do not claim its execution acceptance.
