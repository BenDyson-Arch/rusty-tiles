### Changed

- Breaking validation (VS-A, archive catalog at scale): the admitted ZIP catalog and the report's payload rows no longer grow resident memory with the archive. Each member is one fixed-width row sorted by the `@3dtilesIndex1@` MD5 order (plus a secondary name hash), with names in an append-only log. A catalog that fits 96 MiB (every archive within the default 2^19-entry and 32 MiB directory limits) stays in memory; a larger one moves to a scratch directory, created only at the first spilled file, and is read through a fence table and a 16 MiB page cache. Only one bit per member (the used set, 21.3 MiB at the 178,956,970-member ceiling) still scales with the entry count. Spill is never put in RAM silently: the scratch parent is the first disk-backed directory that has room, in the order `$TMPDIR`, the user cache directory plus `rusty-tiles/scratch` (`$XDG_CACHE_HOME` or `~/.cache` on Linux, `~/Library/Caches` on macOS, `%LOCALAPPDATA%` on Windows; created if missing) and the system temporary directory, skipping memory-backed (tmpfs) ones. When only memory-backed scratch is available, `validate` uses it and the report says so in a new `scratch` member (`memoryBacked`, `peakBytes`), present whenever anything spilled and absent otherwise; the `validate_3tz` facade instead refuses with an I/O error "no disk-backed scratch directory". The index is checked by one streamed merge against the catalog instead of a sort and a binary search per row, name lookups no longer binary-search string names, and the central directory is read in 64 KiB chunks. Verdicts, categories, messages, report counts and payload order are unchanged, with two exceptions. (1) With more than 16 unreferenced members, the message lists the first 16 names in byte order followed by " and K more"; it used to join every name. (2) A failure of the validator's own scratch storage is `io` (exit 1; I/O and free-space refusals), `resource_limit` (size overflow) or `invalid_state` (corrupt scratch), with the prefix "validation scratch:". Breaking Rust API: `ValidationReport::payloads` is `PayloadRows` (length, `get`, iteration and streamed `Serialize`) instead of `Vec<PayloadReport>`; `ValidationReport::summary_json` and `ValidationReport::write_json` are new. The CLI writes the JSON report streamed, byte-identical to before. Python `validate()` returns `report["payloads"]` as a lazy read-only sequence (`ValidationPayloads`) of the same dicts, which supports `len()`, indexing, slicing and iteration but is not a `list`: `report["payloads"] == [...]` is now False and `json.dumps(report)` raises `TypeError`; use `list(report["payloads"])`. Rust `ValidationReport` gains `scratch: Option<ScratchReport>`. The contract is [c1-archive-catalog-scale-amendment.md](docs/architecture/c1-archive-catalog-scale-amendment.md).
