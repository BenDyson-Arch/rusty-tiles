### Fixed

- The CLI now handles SIGINT and SIGTERM (Unix) as a cancellation of the running command. `mesh` and the other spilling commands remove their `rusty-tiles-spill-*`, `.tiles-mesh-*` and `.tiles-stage-*` directories before exiting with status 130 (SIGINT) or 143 (SIGTERM) and a cancelled error, instead of leaving them on disk. A second signal exits immediately. `validate` reports its own cancellation type and exits the same way. The handler is built by the new default `cli` feature (`signal-hook`, Unix only), so the Python bindings, which turn default features off, do not build it. A signal that arrives once cancellation is no longer possible prints "publishing; signal again to force exit".
- The `spill_memory_is_flat_in_input_size` test no longer fails on process-to-process VmHWM noise: it compares the smallest peak of three fresh subprocesses per input size against a documented allowance.
- A test now pins that `escalation_reasons`, the escalation diagnostics and the published bytes of codec-verification escalations are identical for one worker and many.
