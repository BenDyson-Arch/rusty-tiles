### Changed

- `validate`: the default `totalPayloadElements` budget is now max(16 million, 77 × stored bytes), up from 16 ×. Indexed HLOD coarse tiles take fewer stored bytes for the same validation work. The native HLOD delivery check now charges its scratch-store rows (128 units), original vertex rows (16) and placed original keys (32) at their measured cost. The largest validation the test suites log needs 50.75 elements per stored byte, and the ratio is that maximum with a 1.5× margin. For the constant-cost work classes, the admitted work is at most 827 s of CPU per stored GB on a P-core. SQLite rows with random keys get slower as the scratch tables grow, so archives of that kind above about 10 MB stored can take longer (2,052 s per GB at 61 MB). A follow-up will make the per-row cost constant.
- `validate`: the HLOD original-vertex alias check uses a spill sequence and one bounded external sort instead of the SQLite scratch store. This is about 3× faster on leaf-heavy archives, and the verdicts are unchanged, with one exception. An archive with both an alias conflict and a non-finite placed position is now always refused for the non-finite position (`interfaceSegments`). Before, the refusal came from whichever the scan reached first. Both are invalid verdicts.
