### Changed

- Breaking validation (VS-B, traversal and decoded containment at scale): validation memory no longer grows with the tile, reference or payload count. The C2 tile arena, reference list and per-URI table are replaced by a path stack of the current traversal path, and each payload reference whose precheck step passes is streamed at once; its first failure is published only under the unchanged outcome precedence (a C1 failure, then any exclusion, then the precheck reason, then the stream result). Per-URI facts are one 195-byte record per member, kept in memory up to 100 MiB (every archive within the default entry limit) and otherwise in a rank-indexed scratch file. Each record holds the payload's replay receipt: the containment stream no longer re-runs the full C1 inspection of every reference but replays the payload against digests of its own successful first admission, skipping the accessor-value and KTX2 container passes (verdicts unchanged; if the archive changes during validation, a changed member fails with "source archive changed during inspection" before parsing, and a changed external resource can instead fail an earlier size, layout, decoder or I/O check). The external-tileset memo keeps at most 64 MiB of summaries and falls back to full traversal beyond it, with identical results. The tileset schema's `uniqueItems` on `children` is now linear in the document instead of `O(bytes × depth)`, with the same verdicts and messages. Default validation (CLI, Python and Rust `inspect`) scales the seven amplification budgets with the archive's stored member bytes S: `hierarchyVisits` and `references` are at least S/8, `totalBytesRead` and `containmentBytesRead` at least 4·S, `totalPayloadElements` and `containmentDecodedBytes` at least 16·S, and `containmentWorkUnits` at least 128·S; today's values are floors, so archives up to 1 MB of stored bytes keep exactly today's limits, and the report's `limits` shows the effective values. New per-item limit `liveDocumentBytes` (default 256 MiB, in `limits` and `ValidationLimits::live_document_bytes`): the tileset documents on the external-tileset path, charged as raw bytes plus 128 bytes per JSON value node, over which validation is `resource_limit` "live tileset documents exceed N bytes". The I1 availability index tables are now charged to `documentDecodedBytes` with the subtree that holds them ("subtree availability index exceeds the live subtree byte limit"). `notInspected` keeps at most 64 archive-named glTF extension labels (the byte-smallest, each at most 256 bytes); when any is dropped the report gains `notInspectedTruncated: true` (absent otherwise; Rust `ValidationReport::not_inspected_truncated`). The contract is [validator-traversal-scale-amendment.md](docs/architecture/validator-traversal-scale-amendment.md).
