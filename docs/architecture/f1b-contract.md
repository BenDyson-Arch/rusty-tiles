# F1b1: source-faithful base-color textures

Historical resource-admission and report contract. The [F1b2 contract](f1b2-contract.md) now extends this operation to bounded local glTF resources and schema 3. The geometry, material, texture and delivery rules below remain applicable.

First bounded implementation slice of [#121](https://github.com/BenDyson-Arch/rusty-tiles/issues/121), following C1 and the accepted F1a geometry producer. The audit baseline is `fdc5d186faedf80c3d2b4b86556f20e77a970d1f`. This extends the existing `MeshRequest::local_gltf`, CLI `mesh-local-to-3tz`, and Python `mesh_local_to_3tz` operation; there is no second compatibility mode or automatic legacy fallback. #121 and the 0.4.0 gates remain open until their remaining obligations are settled.

## Ownership and retained geometry contract

The consumer owns source binding, the single bounded source snapshot, preparation, selected resource closure, workspace, report, and publication. The source decoder accepts bytes, validates the complete document, and produces owned geometry and image bytes. The leaf encoder accepts only prepared values and resource identities. It never resolves paths, opens source files, launches encoders, discovers dependencies, or publishes output. Runtime continues to own only the F0 attempt and publication lifecycle.

F1a container, selected-scene, transform, normal, reflection, multiplicity, coordinate-domain, spatial partition, bounds and failure rules remain in force except for the explicit additions below. Refer to the [historical F1a contract](f1a-contract.md) for those rules. Every triangle remains full detail; no atlas, simplification, deduplication or geometric repair. Primitive regrouping is allowed only when all supported corner attributes and material associations survive. Source node/primitive/material indices, names and picking identities are not preservation promises.

Leaves retain geometricError 0 relative to the full-detail stored geometry. The contentless root and top-level error remain `max(1 metre, root-box diagonal)`, reported as a routing metric. This does not claim a universal simplification, visual, or source-to-storage Hausdorff bound. Adversarial spike, thin and disconnected fixtures must retain complete leaf coverage; no sampled estimator enters this path.

## Finite source additions

- **Geometry:** optional TEXCOORD_0, f32 VEC2 or normalized unsigned-byte/unsigned-short VEC2. Validate count, component/vertex alignment, stride and actual range. UVs are decoded and stored as f32, finite with absolute components at most 1,000,000. Coordinates outside [0,1] are preserved because sampler wrapping uses them. Each decoded component's storage error is at most `max(1, abs(value)) * 2^-24`; there is no chart transformation. Reflection swaps UV corners with positions and normals. A primitive using a base-color texture must supply TEXCOORD_0. UVs on an untextured primitive are also retained.
- **Materials:** F1a validated factor/alpha/doubleSided fields plus `pbrMetallicRoughness.baseColorTexture`. Texture info accepts `index` and optional `texCoord`; only coordinate set 0 is supported. Field presence and omission are preserved; only numeric dependency indices are remapped. OPAQUE and MASK remain supported. BLEND remains Unsupported because partitioning cannot promise source draw order.
- **Textures:** core texture `source` and optional `sampler`, with validated references. Image source is required in this profile. Names follow the existing descriptive-label policy. All texture, sampler and material objects are checked even if unused or in an unselected scene.
- **Samplers:** preserve absence and all valid core `magFilter`, `minFilter`, `wrapS`, and `wrapT` values, including omission. No sampler defaults are invented or collapsed into equivalent explicit values. Viewers own filtering and mip generation from the delivered image; no resampling or mip encoding occurs here.
- **Images:** embedded bufferView PNG or JPEG with matching explicit `mimeType`, decoding to 8-bit channels. Palette PNGs may use lower packed index depths when decoded color values are 8-bit; 16-bit channels are Unsupported even in unused images. Validate actual bounded image bytes, dimensions and a full decoder pass before admission; a plausible header alone is insufficient. Views used for images must have neither byteStride nor target and cannot also serve accessors. Original encoded bytes are forwarded exactly, including alpha, color information, row orientation and source JPEG losses. This is source-faithful delivery, not a new JPEG quality guarantee. No source image decode is used as a reencoding input.

All other PBR texture channels, TANGENT, TEXCOORD_1, vertex colors, texture transforms, compressed/quantized/sparse geometry, extensions, extras, animation, skins and morphs remain Unsupported anywhere in the document. Their support needs distinct evidence and is not silently inherited from legacy conversion.

## Resource policy and bounds

Source is still one regular non-symlink-leaf GLB, one embedded BIN buffer, source size at most 32 MiB and JSON at most 1 MiB. External glTF documents and every buffer/image URI, including relative, absolute, percent-encoded, data and network URIs, are Unsupported before output work. Thus there is no source URI resolution, base path, escape, external symlink, alias or collision behavior admitted in this slice. External-resource binding remains the next obligation in #121.

At most 32 images, 32 textures and 32 samplers; each image edge at most 4096 pixels, each image at most 4,194,304 pixels, sum of all declared image pixels at most 16,777,216, and sum of copied encoded image bytes at most 32 MiB. These whole-document ceilings include unused images and repeated/overlapping views. Check dimensions and allocation limits before full decode; decode images serially and release decoded storage immediately. The geometry and leaf ceilings remain F1a's. These are finite engineering admission bounds, not measured hard RSS guarantees. No worker pool, configurable image budget, subprocess, external encoder log, or child lifetime is introduced.

Cancellation checkpoints bracket every bounded image decode and byte-copy operation and continue throughout geometry, leaf encoding, image writes, archive serialization and publication. A running image decoder is not preempted mid-call. One source snapshot is used throughout; no source path is reopened after preparation. Length/mtime changes observed during reading are rejected. This does not promise an atomic snapshot against an adversary that mutates a file while restoring observable metadata; a stable source during preparation remains a precondition.

## Closure, delivery and report

Publish each image referenced by selected triangles once as `textures/{source_image_index}.png` or `.jpg`. Names are derived from validated numeric identity and MIME, never source names or URIs. Leaves use `../textures/...` and contain exactly their used material/texture/image/sampler closure with deterministic local remapping. No leaf keeps an unused resource; no unselected or unused image is published. Multiple leaves can reference one shared encoded image without multiplying image scratch or archive bytes.

Exact archive inventory is tileset.json, conversion.json, all accepted leaf GLBs, the selected image closure, and the generated 3TZ index. Consumer writes images to its workspace using the same checked writer and archive inventory as leaf content. All required cleanup completes before final observation and commit. Failure/cancellation/observer error preserves the prior output and accounts for retained paths under F0.

MeshReport now has schema_version 2 and profile `f1b-local-textured-glb-v1`. Existing fields retain meaning. New u64 fields `images`, `image_bytes`, and `image_pixels` count the unique published selected image closure; unused admitted images do not increase them. CLI, Rust, Python and embedded conversion.json must agree. This deliberately replaces the initial F1a report profile instead of maintaining two interpretations of one operation.

## Audit ledger and proof gate

Retain as candidates: bounded source ownership, typed facade, complete-triangle spatial partition, stored-geometry bounds, and F0 lifecycle. Rework: source admission and triangle IR for UVs; leaf attribute grouping and resource remapping; consumer inventory/report for shared images. Exclude from this path: legacy atlas, repeated source path reads, budget-dependent passthrough, simplification, sampled error estimator, global reports and external encoders. Legacy observations are source observations, not newly reproduced conversion defects.

Independent acceptance must author PNG bytes and decode CRC, scanlines, pixels, UVs, material/sampler semantics and oriented triangle associations without production code. It must detect row/alpha/UV/material/sampler corruptions, wrong dependency references, missing/orphan image members and changed encoded bytes with unchanged pixels. Positive JPEG needs independent decoder provenance and exact byte forwarding. Exercise single/many leaves, reflected/interleaved/normalized UVs, repeated textures with different samplers, absent fields, unused images and selected scenes. Verify finite image/source/leaf limits, image-write faults, cancellation, cleanup, source-output aliases, frontend parity and actual viewer appearance/routing. Resource receipts must distinguish process RSS from sampled descriptors/scratch. Test success is acceptance evidence only for this profile.

The remaining #121 slices cover external resource binding, additional material/attribute semantics, placement, metadata/picking, implicit hierarchy, supported approximation/error contracts, and explicit support/removal decisions for advertised legacy uses. This slice neither closes #121 nor authorizes 0.4.0 release.

Primary semantics: [glTF 2.0.1](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), registry commit `8e798b02d254cea97659a333cfcb20875b62bdd4`, especially accessor alignment/normalization, textures/images/samplers and material alpha semantics; [3D Tiles 1.1](https://docs.ogc.org/cs/22-025r4/22-025r4.html) for hierarchy and error routing.
