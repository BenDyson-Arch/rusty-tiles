Full A2 implicit rewriting remains held on its documented normative external
template question. The next dependency-ready foundation is one lossless codec
for physical views in the complete currently generated vector domain, consumed
by the real vector producer and a captured-file in-place operation using F0
Replace. The format owner knows no paths or jobs; standalone owns source capture,
permissions, final source recheck and publication. The producer remains inside
its existing Attempt. The old compression implementation earns no retention
from historical tests or generated bytes alone.

The candidate public Rust operation is `compress_vector_file(request, control)`.
`VectorCompressionRequest::new(input).with_limits(limits)` selects one regular
non-symlink source. `CompressionLimits` exposes finite source bytes, JSON bytes,
JSON depth, JSON value nodes, physical view count, accessor count, logical bytes,
candidate bytes and requested working bytes. The default policy is 32 MiB source,
1 MiB JSON, depth 64, 65,536 nodes, 4,096 views, 4,096 accessors, 32 MiB logical,
64 MiB candidate and 128 MiB working storage. Joint working refusal can occur
below individual maxima. The working estimate excludes allocator overhead,
global OOM, RSS, and the producer's existing geometry construction storage.

The operation captures identity and bytes before callbacks, drops source handles,
rechecks source spelling, identity and full bytes before replacement, and copies
ordinary Unix permission bits before sealing. The caller keeps the namespace
stable through publication; named-entry Replace provides no compare-and-swap
guarantee. Windows readonly sources are rejected before callbacks or staging.
Unsupported representations and invalid input remain typed failures; cleanup
after commit is returned as diagnostics on success. The hidden
`encode-vector-content --input PATH` adapter emits the already prepared JSON
report. No Python compression entry point is added.

The producer resolves raw or compressed encoding once and shares it between
fitting and final emission. Its `uncompressedTileBytes` metric now counts the
actual selected-framing raw bridge after requested quantization, including the
fill wrapper. `uncompressedTileBytesScope` states that boundary explicitly.
Prequantization geometry size is no longer used as this byte metric. The actual
paired producer output/report checks above cover its finite observed cases;
optimal fitting and broader resource guarantees remain separate obligations.
