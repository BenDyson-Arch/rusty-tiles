rusty-tiles 0.4.2 makes `mesh` coarse levels complete and honest, and makes it faster and lighter:
- every coarse cell and the root are published on the public test models, and a recovered root covers large models whose middle levels still fail;
- coarse tiles publish a certified geometric error;
- `mesh` is 14–46% faster than 0.4.1 on the measured inputs, with up to 8× less peak memory.

It also adds `mesh-inspect`, a fast pre-bake check of a mesh source, and new `mesh` options for welding, baking part of a source and writing a run report.

## Install

- **CLI:** `curl -fsSL https://raw.githubusercontent.com/BenDyson-Arch/rusty-tiles/main/scripts/install.sh | sh` (Linux x64/ARM64, Apple Silicon macOS). For Windows x64, download the `.zip` below. Every archive is listed in `SHA256SUMS`.
- **Python:** `python -m pip install rusty-tiles`. These are CPython 3.10+ stable-ABI wheels for Linux x64/ARM64, Apple Silicon macOS and Windows x64. They need no GDAL and are tested inside Blender 4.5 LTS and 5.2 LTS.
- **Native-geospatial build:** `ghcr.io/bendyson-arch/rusty-tiles:v0.4.2` (Linux amd64).
- **From source:** `cargo install --git https://github.com/BenDyson-Arch/rusty-tiles --tag v0.4.2 --locked`

Intel macOS is not supported (0.4.0 is the last release with it).

## Highlights

- **Complete coarse levels.**
  - Cells that 0.4.1 omitted now build: P1, a new guard-by-construction contraction, runs before the retry ladder, and a failed cell keeps the border vertices P1 cannot remove instead of giving up.
  - An omission no longer costs the root (root recovery v2). Each omitted cell passes up an unpublished stand-in, the root builds over the built cells and the stand-ins, and it is delivered over the whole published frontier (up to 384 tiles).
  - On the public test models below, 0.4.2 publishes every coarse cell and the root. 0.4.1 omitted the root on the rock and the city. On a private 390M-triangle terrain model, which had no root on earlier builds, the root now covers 172 frontier tiles and the archive passes `validate` end to end.
- **Certified geometric error.** Coarse tiles publish a two-sided error bound over the original source and the decoded surfaces, including edge and face interiors, instead of a sampled estimate. Tiles that understated their error now refine earlier in a viewer.
- **Faster and lighter.** 0.4.1 against 0.4.2, `mesh` with production defaults, 4 workers on 2 cores (4 SMT threads) of a Ryzen 7 5700U, `--memory-budget 4GiB`, two alternating pairs per input:

  | input | wall, 0.4.1 → 0.4.2 | CPU | peak RSS | omitted cells, 0.4.1 → 0.4.2 |
  | --- | --- | --- | --- | --- |
  | #344 rock (4.9M triangles) | 106 → 76 s (−28%) | −11% | 0.47 → 0.41 GiB | root and 5 cells → none |
  | 10M-triangle synthetic city | 882 → 758 s (−14%) | −16% | 4.14 → 0.52 GiB | root and 16 cells → none |
  | photogrammetry site (10M triangles) | 1,898 → 1,017 s (−46%) | −35% | 2.13 → 1.10 GiB | 1 cell → none |

  - Capture is 2–3× faster: parallel cell trees, direct triangle assembly, fewer sorts and LZ4-compressed scratch streams.
  - The coarse stage no longer decodes source images, so it needs less memory and runs more jobs at once. Leaf UASTC encoding uses less CPU.
  - On large models the root tile, which builds alone, runs its error searches in parallel. On the 390M-triangle model the root cell fell from 527 s to 407 s.
  - Root errors are not comparable between the versions: 0.4.1 published a sampled error and 0.4.2 a certified one, which is larger by design.
- **`mesh-inspect`.** A pre-bake check of a mesh source that writes no archive: open edges and loops, primitive seams, repeated positions, components and a weld preview, with exact counts. It reads the source once and takes about 1% of a bake's time (54 s on an 80M-triangle copy of the photogrammetry site). `--forecast` adds an estimated coarse-omission risk per cell, at the cost of most of a bake.
- **New `mesh` options.**
  - `--weld-epsilon METRES` and `--join-primitives same-material` weld vertex positions before capture. Error is still certified against the original source.
  - `--bbox` and `--polygon` bake only part of a source, lined up with a later full bake.
  - `--report-path FILE` writes a versioned JSON run report after each stage, so a stopped run leaves a valid partial report.
- **Validation.**
  - `validate --coarseCrossings` reports coarse self-intersections: pairs of faces of one coarse tile that meet anywhere but a shared vertex or edge, split into those its children already have and new ones. It never changes a verdict. It is opt-in because it adds 9–41% to validation time.
  - Validation accepts root recovery version 2, and no longer refuses a coarse tile that keeps a collinear source face unchanged.
- **Other.**
  - The opt-in cargo feature `pure-rust-basis` encodes and decodes KTX2 textures in pure Rust, byte-identical to the default build.
  - `preview` lights the scene with a fixed sun, so the view no longer depends on the time of day.

## Breaking and behaviour changes

rusty-tiles is pre-1.0, so options, APIs, report fields, error types and archive bytes can change in any release. Pin a version for anything you depend on.

- **Archive bytes change** for `mesh`:
  - coarse tiles carry the certified geometric error, which is usually larger than 0.4.1's sampled one, so viewers refine to finer levels sooner;
  - cells that 0.4.1 omitted are now published;
  - a recovered root declares recovery version 2, and version 1 is no longer produced (the validator still accepts it);
  - leaf KTX2 textures use Basis Universal's fastest ETC1 hints: archives are 0.3–0.7% smaller, decodes to RGBA, ASTC, BC7 and BC1/3 are unchanged, and the ETC1 transcode (only for GPUs without ASTC, BC7 or S3TC) loses about 0.6–0.7 dB.
- **Memory:** the coarse stage's minimum memory rises by about 28 MB for the root's error searches.
- **Rust API:** `TilerDiagnostics` is `#[non_exhaustive]`, so it can no longer be built with a struct literal outside the crate.
- **`RUSTY_TILES_STAGE_TIMING`** is read by the CLI, and its file is written only after a successful `mesh` run.
- **Building from source** uses the pinned Rust 1.100.0 toolchain (`rust-toolchain.toml`); rustup installs it on first use. Running the test suite needs Python 3.12 or newer, which generates the validator fixture corpora.

## Known limitations

- On very large irregular surfaces some middle coarse levels can still be omitted. The root is published over them, so a viewer refines from the root straight to the frontier below the omitted cells and loads those tiles together. Full-detail leaves are always delivered, and `conversion.json` and `validate` report what was left out. Publishing those levels (skirted stand-ins) is planned (#344).
- On large models the root tile's sampling stream is still serial and leaves the other workers idle (about 400 s on a 390M-triangle model). Tracked in #343.
- `mesh-inspect --forecast` costs most of a bake, and its estimate is modest: on four measured bakes it found 3 of 18 omission sources.
- `validate --coarseCrossings` runs serially.
- Vector output is experimental.
